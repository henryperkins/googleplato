# Design System: plato

## Overview

**Creative North Star: "The Learning Workspace"**

The existing interface is **direct, structured, and compact**, with **structured and familiar** components. It organizes learning and administration around clear headings, small controls, bounded content areas, and lightly outlined surfaces. **Plato Purple** anchors administration; configurable classroom identity supplies the learner-facing accent.

The system is **lightly layered, with restrained structural shadows**. Geist supplies the interface and learner-message typography. Coach replies use a system serif, creating a visible distinction between the two voices. Cards, form controls, navigation items, and message bubbles share a gentle corner language with different radii for different roles.

This is a record of the implemented system. Values come from [index.css](client/src/index.css), the [UI primitives](client/src/components/ui/), [branding utilities](client/src/lib/branding.js), and the installed Tailwind theme. Local Chromium inspection covered administration, the lesson list, and a resumed conversation at desktop (1440 px) and mobile (390 px) widths, using temporary sample records in an isolated database. Dark token overrides were sampled separately. These checks establish styles and layout observations, without certifying accessibility or live service behavior. The structure follows the [DESIGN.md format](https://raw.githubusercontent.com/google-labs-code/design.md/main/docs/spec.md).

**Key Characteristics:**

- Direct, structured, and compact presentation.
- Structured and familiar controls with a modest corner scale.
- Plato Purple administration and independently branded classrooms.
- Geist interface typography and system-serif coach replies.
- Light tonal layers, fine outlines, and restrained structural shadows.

The palette combines a deep purple administration accent, high-contrast neutrals, configurable classroom colors, and functional progress states. Exact values live in the frontmatter; the names below describe their use.

Foregrounds are selected by contrast ratio, with a black fallback when neither white nor near-black reaches 4.5:1. Separate `primary-text` and `link` roles adjust failing text colors for light and dark surfaces. The customizer preview uses the same derivation as the classroom.

### Functional states

- `destructive` identifies errors and destructive actions. Its light foreground is dark enough for the tinted error surfaces.

- `completed-background` and `completed-foreground` identify the completed lesson indicator. `completed-progress` records the green used by high-completion admin rings; the completed chat bar and check use `success-foreground` in both themes.

- `ring` supplies the standard focus color, including classroom overrides.

**The Classroom Boundary Rule.** Apply saved classroom identity to learner and auth surfaces. Keep the administration identity independent of those settings.

## Typography

**Interface font:** Geist Variable, with the system sans-serif fallbacks recorded in the frontmatter. The same family is used for headings, controls, metadata, and learner messages. The variable font is bundled locally.

**Coach font:** The system serif stack recorded under `typography.coach`. Coach replies use this stack at body size; no separate serif font asset is loaded.

The hierarchy is practical and closely spaced. Weight and context do much of the work. There is no extracted oversized display treatment or fixed scale ratio.

| Role | Typical use | Observed size / weight |
| --- | --- | --- |
| `headline` | Admin page headings and prominent statistics | 24 px / 700 |
| `heading` | Learner page and settings headings | 20 px / 600 |
| `subheading` | Admin section headings | 18 px / 600 |
| `title` | Default card titles | 16 px / 500 |
| `lesson-title` | Lesson names inside cards | 16 px / 600 |
| `body` | Learner messages and base text | 16 px / 400 |
| `coach` | Coach-message text | 16 px / 400, serif |
| `body-small` | Descriptions, admin content, and composer text | 14 px / 400 |
| `button`, `label` | Actions and form labels | 14 px / 500 |
| `caption`, `badge` | Metadata and compact state labels | 12 px / 400 or 500 |

Lesson descriptions use a relaxed line height (1.625). Form labels use a tight line height (1). Native input primitives and the chat composer use body size on narrow screens and small-body size from the medium breakpoint.

Exceptions remain local: auth card titles can use headline size with medium weight, dialog titles use 16 px / 500 with a tight line height, and course labels in lesson outlines use uppercase text with wider tracking. Statistics use tabular numerals where declared.

**The Two Voices Rule.** Keep learner messages in Geist and coach replies in the existing serif stack. Preserve their alignment and surface treatment alongside the font distinction.

The coach markup uses the lightweight renderer in [helpers.js](client/src/lib/helpers.js). Its scoped `coach-copy` styles give unordered and ordered lists their markers, compact item spacing, and 24 px indentation. Links use the accessible link color with a persistent underline; long addresses wrap within the message width. This formatting does not depend on a typography plugin.

## Layout

The spacing unit is a quarter rem (4 px at the inspected root size). The app uses half steps and larger multiples, rather than a strict 8 px-only grid. Common content padding is 16 px; admin pages use 24 px; card and section gaps are usually 12–16 px.

| Surface | Container and responsive behavior |
| --- | --- |
| Learner shell and lesson list | Centered, up to 64 rem (1024 px), with 16 px page padding. |
| Lesson grid | One column initially, two from 40 rem (640 px), three from 64 rem (1024 px); 12 px gaps. |
| Chat and composer | Centered, up to 48 rem (768 px); messages occupy at most 85% of the conversation width. |
| User settings | Centered, up to 32 rem (512 px). |
| Auth card | Up to 28 rem (448 px), within a full-height branded page. |
| Administration | A fixed 14 rem (224 px) sidebar from 48 rem (768 px), with matching content offset; content is capped at 56 rem (896 px). |
| Mobile administration | A top bar and modal 16 rem (256 px) drawer replace the sidebar; it is capped to the viewport, contains keyboard focus, closes on Escape, and restores focus to its trigger. |
| Standard dialog | Viewport width minus 32 px on small screens; up to 32 rem (512 px) from the small breakpoint. |
| Authoring workspaces | Vertical stack initially; conversational editor and preview form a 3/5–2/5 split from the large breakpoint. |

Filters stack on narrow screens and align horizontally from the small breakpoint. Dashboard grids vary by information density: summary cards use one then two columns; compact pacing statistics use two then three. Dialog actions stack in reverse order on small screens and align right in a row from the small breakpoint.

The chat uses one accessible sticky header and document scrolling. Its title and overview stack on narrow screens and wrap with enlarged text. The composer retains inline and elevated variants; the inactive copy is inert and the elevated copy carries a stronger shadow. Admin action and filter rows wrap at narrow widths. Preserve scroll and focus behavior when altering this layout; [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) records the relevant constraints.

**The Bounded Content Rule.** Extend the existing container appropriate to the surface. Keep conversation text within the narrower chat width and preserve the mobile stack before introducing additional columns.

## Elevation & Depth

Depth is lightly layered and structural. Cards usually rest on a fine outline with a white or tonal surface. Lesson cards gain a medium shadow on hover. Menus and pinned elements use a medium shadow, and the elevated composer uses a large one. Standard dialogs use a fine outline, a translucent backdrop, and a small supported backdrop blur; their component does not declare a large drop shadow.

### Shadow vocabulary

- **Fine card outline:** A 1 px ring using foreground at 10% opacity.
- **Small control lift:** The existing `shadow-sm` value on native select filters.
- **Medium lift:** The existing `shadow-md` value on hovered lesson cards and dropdowns. The sticky lesson header uses its thin bottom boundary.
- **Large lift:** The existing `shadow-lg` value on elevated composers and submenu panels.

The exact shadow values are in `.impeccable/design.json`. The dialog backdrop uses black at 10% opacity with a supported 4 px blur. The mobile drawer backdrop uses black at 40% opacity. These treatments distinguish blocking overlays from ordinary content.

Interaction transitions generally use 150 ms with the installed standard easing. Dialog and menu transitions use 100 ms. The mobile drawer slides in over 220 ms and out over 140 ms, with a separate 160 ms backdrop fade. Drawer arrivals and progress changes use `cubic-bezier(0.16, 1, 0.3, 1)`. Progress fills scale from the left over 280 ms while their semantic color settles over 150 ms; they do not animate layout width. Lesson cards appear immediately, without delayed entry choreography.

The focal motion acknowledges demonstrated mastery: the check beside **Exemplar Achieved!** draws once over 520 ms after the completion reply finishes. Its label, success color, and full progress bar are immediately readable. Resuming a completed lesson shows the finished check without replaying it. The effect cancels on navigation, backgrounding, or a change to reduced motion; completion and persistence remain owned by the lesson engine.

With `prefers-reduced-motion: reduce`, the completed check is static, progress changes position immediately, the drawer fades without sliding, and shared dialogs/menus retain their fades without zoom or translation. Button presses and switches avoid movement, and loading indicators keep their status text without rotating. Streamed replies display received chunks without the artificial typing delay. Color, focus, and opacity feedback remain available.

Routine route changes are immediate. The unused transition-marker hook has been removed; navigation does not add route choreography.

## Shapes

The base radius is half a rem. The app defines its own multipliers, which override the installed Tailwind defaults.

| Scale | Observed role | Size at the inspected root |
| --- | --- | --- |
| `sm` | Learner-bubble trailing corner | 4.8 px |
| `md` | Compact buttons, navigation items, and native select controls | 6.4 px |
| `lg` | Default controls and composers | 8 px |
| `xl` | Cards and dialogs | 11.2 px |
| `2xl` | Learner-message bubbles and authoring containers | 14.4 px |
| `4xl` | Compact badge ends | 20.8 px |

Status indicators and progress bars use fully rounded shapes. Learner-message bubbles narrow their lower-right corner; coach replies remain an unboxed text block. Standard boundaries are thin and neutral; card outlines are rings rather than ordinary borders.

**The Existing Radius Rule.** Use the project's radius variables. A Tailwind utility name resolves to this custom scale, so importing stock Tailwind or another shadcn preset's numeric values would change the shape language.

## Components

### Buttons

Structured and familiar, with compact sizing and a clear variant API. The common radius is `rounded.lg`; the smaller sizes use `rounded.md`. Primary buttons fill with the current primary color, outline buttons retain a thin boundary, secondary buttons use a neutral fill, ghost buttons reveal a muted hover surface, destructive buttons use a tinted error surface, and link buttons underline on hover.

| Size API | Height | Horizontal padding / shape |
| --- | --- | --- |
| Default | 40 px | 16 px padding, 8 px corners |
| `xs` | 24 px | 8 px padding, 6.4 px corners |
| `sm` | 28 px | 10 px padding, 6.4 px corners |
| `lg` | 36 px | 10 px padding, 8 px corners |
| Icon sizes | 24 / 28 / 32 / 36 px | Square controls using the corresponding size |

These are compact desktop dimensions. Below 640 px or when a coarse pointer is available, shared buttons and explicitly marked touch controls have a minimum 44 × 44 px hit area. The existing `lg` height is smaller than default; preserve actual dimensions rather than inferring them from the name. Default text is 14 px / 500, small text is 0.8 rem, and extra-small text is 12 px. Icons are usually 16 px, with smaller icons on smaller controls.

Shared button focus uses a ring-colored border and a 3 px ring at 50% opacity. Other keyboard-focusable controls have a solid 3 px outline consuming the complete ring color; colored headers use their contrasting foreground for focus. Account labels match the rendered name. Disabled controls reduce opacity and pointer interaction. Invalid controls use destructive border and ring colors. Pressed buttons move down 1 px unless they expose a popup. The primary background hover treatment is currently declared for anchor-rendered buttons; do not assume the same fill change on a native primary button.

### Inputs and textareas

Structured, thinly bounded fields with 8 px corners and a transparent base surface. Text inputs are 40 px tall with 12 px horizontal and 8 px vertical padding. Textareas have a minimum height of 64 px and size to content. Dark fields add a faint input-color fill. Placeholder text is muted; focus and invalid states follow the button ring vocabulary.

Keep labels, help text, validation wording, and accessible names connected to the control. The chat composer is its own textarea inside a bordered container, with attachment tools and a send action; it does not share every generic textarea style.

Password visibility controls remain centered through press states and disable with their input. On narrow screens or coarse pointers, password fields expand to 44 px to contain the toggle's touch target. Settings uses a page heading and section headings, explicit saving/disabled states, and persistent success or error feedback in live regions. Editing or resubmitting clears the previous feedback. The profile-feedback dialog exposes request errors, supports retry, and resets its submitting state after completion. Long email addresses wrap beneath their label on narrow screens.

### Badges and status indicators

Badges are compact (20 px high), medium-weight labels with highly rounded ends. Primary, secondary, outline, destructive, ghost, and link variants reuse the existing semantic colors. Anchor-rendered badges have their own hover behavior.

Lesson status is a separate visual language: a completed check on an emerald wash, an active ring on an amber wash, and an unstarted neutral circle. Visible state and accessible status wording accompany these symbols.

### Cards and lesson cards

Default cards use the card surface, 11.2 px corners, a fine foreground ring, 16 px vertical padding, and 16 px internal gaps. Header and content sections add horizontal padding. Footer sections use a top border and a muted half-opacity background.

Lesson cards override the outer padding and gap. A title-first open action occupies the upper region; a separate metadata strip and “View outline” action sit below it. Descriptions are clamped to two lines. The outline action is a sibling of the open action. Hover adds medium elevation and colors the title with the accessible `primary-text` role. Inactive plugin cards retain full text opacity and communicate their state with a label and switch.

### Navigation

Administration uses a purple navigation surface with light text. Items have 6.4 px corners and 12 px horizontal / 8 px vertical padding. The current item has a 20% light wash and medium weight; inactive items gain a 10% wash on hover. Mobile reuses the same items in an accessible modal drawer. The sidebar semantic surface matches Plato Purple in light mode and becomes a dark purple surface in the prepared dark variant. User tables preserve native row/cell semantics and expose editing through a named button in the name cell.

The learner shell uses a branded header, a classroom name or logo linking to lessons, an account menu, and a small attribution footer. The account trigger underlines on hover to preserve contrast with custom header colors. The admin strip is a separate fixed-color identity layer. Preserve skip links and accessible navigation names.

### Conversation and progress

Coach replies align left as unboxed serif text. Learner replies align right as primary-filled Geist bubbles with contrasting text, 16 px horizontal / 12 px vertical padding, and a tighter lower-right corner. Both are limited to 85% of the chat width. Images and link attachments follow the learner side of the conversation.

The composer uses the background surface, a thin input-colored boundary, and an 8 px radius. Attachment chips keep their own link and remove affordances. The progress track is a thin, fully rounded muted line, filled with accessible primary emphasis while active and green when complete. The composer uses 16 px text below the medium breakpoint and 14 px above it, retains an unclipped minimum line height, and resizes after text, width, font, or root text-size changes; long responses scroll within its 200 px height cap.

Preserve the silent chat log, separate announcements, keyboard message navigation, and exclusion of streaming text from screen-reader focus. Partial streaming messages are inert so their links cannot receive keyboard focus until the reply is complete. Chat back/reset actions use the same stroked SVG icon family as other controls. These interaction constraints are recorded in [PRODUCT.md](PRODUCT.md).

### Dialogs, menus, and empty states

Dialogs and menus use popover surfaces, rounded containment, and compact spacing. Dialogs are centered; menus attach to their trigger. Dialog footers use a muted layer to group actions. Focus and dismissal behavior come from the existing Base UI / Radix primitives and their wrappers.

Lesson-list loading and empty states use a dashed, rounded boundary, centered text, and roomy vertical padding. Distinguish an empty classroom, an empty filter result, and loading through their existing wording and status announcements.

Lesson preparation uses the shared card surface and spacing. Step labels stay visible while semantic primary, success, and muted colors distinguish active, complete, and pending steps in light and prepared dark themes. Reduced motion retains the labels and static status icons.

## Do's and Don'ts

### Do:
